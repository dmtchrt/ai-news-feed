# AI News Feed — PRD v0.1
_27.08.2026_

## Проблема
Новостей слишком много, они дублируются в разных источниках, окружены рекламой и мусором,
и за всем этим приходится следить вручную. Нужна личная лента, которая собирает материалы
только из выбранных пользователем источников, убирает повторы и рекламу, суммаризирует
и всегда даёт ссылку на оригинал.

## Пользователь MVP
Один владелец конфигурации — Дима. Канал с дайджестом можно расширить на ещё одного
человека (например, друга) через инвайт-ссылку — у всех участников канала общий список
источников и общая лента, без отдельных профилей на человека. Полноценный
многопользовательский режим (у каждого свои источники/настройки), регистрация, биллинг —
не сейчас.

## Основной сценарий
1. Пользователь один раз настраивает список источников (сайты/RSS + Telegram-каналы) и
   описывает текстом, что ему интересно (одна или несколько тем).
2. Система периодически опрашивает источники (например, несколько раз в день).
3. Новые материалы приводятся к общему формату и группируются по теме (дедуп/кластеризация).
4. Каждый кластер проверяется одним LLM-вызовом на рекламу/шум и на релевантность
   заявленным интересам — не прошедшие проверку дальше не идут.
5. Прошедшие проверку кластеры суммаризируются в короткий пункт со ссылками на все
   статьи-источники.
6. Дайджест приходит в приватный Telegram-канал, где бот — админ и публикует посты; под
   каждым постом доступны комментарии через привязанную к каналу группу-обсуждение. Если
   за прогон не нашлось ни одного релевантного кластера — дайджест не отправляется.

## Скоуп MVP
- Источники: сайты (RSS/скрапинг) + публичные Telegram-каналы.
- Доставка: приватный Telegram-канал (бот — админ, публикует дайджесты) + привязанная
  группа-обсуждение для комментариев под постами — штатная функция Telegram, отдельно
  разрабатывать не нужно. Канал можно расширить ещё на одного человека без изменений
  в пайплайне.
- Обработка: дедуп/кластеризация по смыслу → фильтр релевантности интересам и
  рекламы/шума (один LLM-вызов на кластер) → суммаризация только прошедших кластеров.
- Интересы задаются свободным текстом (одна или несколько тем) через личные сообщения
  боту, редактируются в любой момент так же, как список источников.
- Список источников настраивается через личные сообщения боту (не в канале) или
  конфиг-файл в репозитории.
- Если ни один материал за прогон не прошёл фильтр релевантности — дайджест не
  отправляется; это нормальный результат, а не ошибка.
- Универсальный fallback независимо от источника: переслать сообщение / прислать ссылку боту,
  чтобы материал обработался как любой другой источник (полезно для всего, что не доступно по API).

## Явно не делаем в MVP (non-goals)
- YouTube, VK, Facebook-Pages — Фаза 2 (см. ограничения ниже).
- Facebook-группы — не планируем: программный доступ закрыт (см. ниже).
- Веб-интерфейс, мобильное приложение — бота достаточно на старте.
- Неявная персонализация на основе поведения (реакций пользователя) — Фаза 2 (см. ниже).
  Явная фильтрация по заданным текстом интересам — часть ядра MVP, это не то же самое.
- Анализ комментариев/заметок под постами как сигнала для ранжирования — сама возможность
  их оставить есть с первого дня (штатная функция Telegram), но бот их не читает и не
  использует в MVP.
- Полностью автономная оркестрация агентов — на старте PO вручную дирижирует сессиями
  агентов; автоматизация самого оркестрирования — отдельный проект после того, как продукт заработал.

## Фаза 2 (зафиксировано, но не в текущем спринте)
- Репост новости из источника без изменений (с сохранением ссылки/атрибуции) в канал,
  если у оригинала просмотры/реакции выше заданного порога — для случаев, когда хочется
  ретранслировать хайповое как есть, без суммаризации.
- Влияние реакций читателя на посты бота на будущую ленту (неявная персонализация поверх
  явного фильтра интересов). Технические детали — в ARCHITECTURE.md.

## Ограничения по источникам (проверено 27.08.2026)
- **Facebook-группы**: Meta закрыла программное чтение ленты групп для сторонних приложений
  в апреле 2024, ограничение действует и в 2026. Работают только публичные Страницы (Pages)
  через Graph API. Группы — только через ручную пересылку постов в бота.
- **VK**: сообщества читаются через официальный API с токеном приложения, но VK регулярно
  и без предупреждения меняет ограничения — проверять актуальные условия непосредственно
  перед началом работы над этим коннектором, не раньше.
- **YouTube**: Data API v3, 10 000 бесплатных единиц в день. Отслеживать новые видео через
  playlistItems.list по служебному плейлисту «загрузки» канала (1 единица за страницу,
  ID плейлиста = ID канала с заменой UC → UU), не через search.list (100 единиц за вызов).
- **Telegram**: публичные каналы читаются обычным пользовательским аккаунтом через
  MTProto-библиотеки (Telethon/Pyrogram), без одобрения бота — стандартная практика.

## Бюджет и его последствия для архитектуры
~$50 суммарно + уже оплаченные подписки Claude и ChatGPT. Подписки покрывают саму
разработку (Claude Code / Codex CLI) — использовать их для регулярного автоматического
прогона продукта (суммаризация по расписанию 24/7) не стоит: это отдельный вид нагрузки,
на который лучше закладывать небольшой API-бюджет из $50, а не рассчитывать на лимиты
личной подписки. Отсюда — требование к архитектуре: по умолчанию бесплатные хостинг
и инструменты, платный LLM-вызов — только на этапе суммаризации, и по одному вызову
на кластер новостей, а не на каждую статью. Подробности — в ARCHITECTURE.md.

## Критерии успеха MVP
- Дайджест приходит в Telegram-канал регулярно и автоматически, без ручного запуска
  (или не приходит вовсе, если за прогон не нашлось ничего релевантного — это тоже успех).
- Без дублей одной и той же новости из разных источников.
- В дайджесте нет материалов не по теме заявленных интересов.
- Каждый пункт — короткая суммаризация + рабочая ссылка на оригинал.
- Заметно меньше рекламы/шума, чем при прямом чтении источников.
- Стоимость эксплуатации укладывается в бюджет.
