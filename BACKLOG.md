# Бэклог — Фаза 0/1 (тонкий сквозной срез)
_27.08.2026_

Цель фазы: один источник каждого MVP-типа → дедуп → суммаризация → сообщение в Telegram,
работающее end-to-end, прежде чем расширяться на остальные источники и фичи.

## 0. Подготовка (PO)
- [x] Завести git-репозиторий для проекта.
- [x] Завести Telegram-бота через @BotFather, сохранить токен.
- [x] Выбрать источники — собран полный список (см. SOURCES.md); для первого
      теста предложен урезанный набор (отмечен ★ в файле), ждёт подтверждения PO.
- [x] Сформулировать текстом первую версию своих интересов (одна-две темы) — понадобится
      AI/ML-инженеру для фильтра релевантности. См. INTERESTS.md.
- [ ] Лично прогнать RSS-Bridge на этих 2–3 Telegram-каналах и паре сайтов без RSS —
      убедиться, что результат реально устраивает, прежде чем закладывать это в архитектуру.
- [x] Создать приватный канал, добавить бота админом с правом публикации.
- [x] Привязать к каналу группу-обсуждение (Discussion) для комментариев под постами.
- [ ] Если бот должен читать комментарии — добавить его и в группу-обсуждение, отключить
      Privacy Mode через @BotFather до добавления бота в группу.
- [ ] Если делаем канал на двоих — позвать друга инвайт-ссылкой в канал и в группу.

## 1. Архитектор
- [ ] Прочитать код auto-news и проверить вывод RSS-Bridge перед финализацией модулей
      (находки — в RESEARCH.md).
- [ ] Уточнить ARCHITECTURE.md под конкретный язык/фреймворк (например, Python).
- [ ] Разбить пайплайн на модули, описать интерфейсы между шагами (вход/выход каждого).

## 2. Инженер по источникам
- [ ] Коннектор RSS/сайтов: получение новых материалов + извлечение текста.
- [ ] Коннектор Telegram-каналов: сначала через RSS-Bridge; Telethon — запасной вариант,
      если не хватит гибкости.
- [ ] Вложения-документы в Telegram (PDF/DOCX-отчёты, например у @expertosphere):
      RSS-Bridge отдаёт только имя и размер файла, не содержимое (проверено по исходнику
      бриджа) — нужен путь через Telethon: скачать документ + извлечь текст.
- [ ] Приведение всех типов к общему формату (заголовок, текст, ссылка, дата, источник).

## 3. AI/ML-инженер
- [ ] Дедуп: хэш-фильтр на точные повторы + SemHash на семантические дубли (см. RESEARCH.md).
- [ ] Фильтр релевантности и рекламы/шума: один LLM-вызов на кластер, дешёвая модель,
      числовая оценка (не только да/нет), при сомнении — пропускать дальше. Критерии
      релевантности — из текста интересов пользователя (см. PRD.md).
- [ ] Суммаризация кластеров, прошедших фильтр, в дайджест-пункт со ссылками на все
      исходники.

## 4. Backend/инфраструктура
- [ ] SQLite-схема (источники, интересы, материалы, кластеры, оценка релевантности,

- [ ] GitHub Actions workflow: расписание + запуск пайплайна.
- [ ] Отправка дайджеста в Telegram-канал через Bot API (бот — админ канала).

## 5. Ревьюер
- [ ] Проверка каждого шага по критериям из PRD.md перед приёмкой PO.
- [ ] Кросс-ревью: модуль от Codex ревьюит Claude, и наоборот.

## Definition of done для Фазы 0/1
Дима автоматически получает в Telegram-канал дайджест по своим источникам и заявленным
интересам — без дублей и без материалов не по теме, с рабочими ссылками — минимум раз в
день, или тишина, если по теме ничего не нашлось, без ручного запуска.
